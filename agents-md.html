Deep dive

AGENTS.md turns local engineering judgment into executable guidance.

Put stable repository rules where every agent can read them: setup, architecture boundaries, naming, validation commands, review expectations, and when to stop for humans.

What belongs there

Encode rules that affect edits.

  • Environment setup: Node version, pnpm commands, local services, and test prerequisites.
  • Architecture boundaries: package ownership, DTO location, persistence contracts, and adapter rules.
  • Code shape: naming, SQL command style, logging, comments, and module layout.
  • Verification: fast local checks, CI-parity command, coverage expectations, and PR evidence.
  • Safety: human gates for migrations, production data, deploy promotion, and risk acceptance.

What does not

Keep always-loaded guidance short.

  • Do not paste long tutorials or temporary task context into repo-wide guidance.
  • Move detailed workflows into skills, playbooks, or docs linked from AGENTS.md.
  • Use path-specific guidance only when rules differ by package or subsystem.
  • Retire rules that no longer match the codebase, CI, or review practice.

Example

A compact AGENTS.md skeleton.

Repo guidance

# Repository Guidance

## Setup
- Run `nvm use` from the repo root before Node or pnpm commands.
- Use `pnpm install` with the committed lockfile.

## Architecture
- Keep public HTTP DTOs in the contract package.
- Put repository and store interfaces in the ports package.
- Runtime packages compose adapters; they do not define persistence contracts.

## Validation
- During implementation, run `pnpm fix`.
- Before PR handoff, run the focused tests for touched behavior.
- For high-risk changes, run `pnpm verify:ci`.

## Review
- PRs must include summary, testing, release impact, docs, and not-tested gaps.
- Run independent AI quality and security review before human review.
- Human approval owns merge, risk acceptance, and production promotion.
