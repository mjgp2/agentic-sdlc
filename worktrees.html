Deep dive

Worktrees make agent work isolated and cheap to restart.

A Git worktree is another checkout of the same repository with its own branch and working directory. For AI coding, it gives each story or review-fix batch a contained execution lane: one task, one branch, one reviewable diff.

Operating pattern

The spec defines the boundary; the worktree contains the attempt.

01

Name the lane

Use the ticket or story id in the branch and folder name.

02

Bootstrap quickly

Bound context

Give the agent the ticket, relevant files, diagrams, logs, and expected proof.

Verify and hand off

PR ready

TypeScript setup

Optimize for frequent fresh lanes.

  • Load the repo Node version with nvm use.
  • Use the workspace lockfile and shared pnpm store.
  • Keep pnpm install warm-path fast enough that creating a worktree is not a big decision.
  • Document Docker/local service startup for integration and functional lanes.
  • Avoid worktree-local mystery state; setup should be reproducible from repo text.

Parallel agents

Parallelize without edit races.

  • Use separate worktrees when multiple agents may edit code.
  • Assign file ownership or task slices before parallel implementation starts.
  • Use read-only subagents freely for investigation and verification.
  • Merge findings through one owner who decides what reaches the PR.
  • Checkpoint before long-running cleanup or multi-agent work.
