Deep dive

Architecture choices need to be repo text, not chat memory.

Agents follow the context they can inspect. Put boundaries, data shape, diagrams, ADRs, and rejected options into durable files so implementation stays aligned with the system.

Architecture artifacts

Use the lightest durable artifact that explains the decision.

  • ADR for a choice with tradeoffs or rejected options.
  • Mermaid sequence diagram for cross-service or retry-heavy behavior.
  • State diagram for lifecycle/status transitions.
  • Data-flow or threat model for trust-boundary changes.
  • ERD/database diagram for persistence, migration, or ownership changes.

Agent checks

Use AI to challenge diagrams before code exists.

  • Ask what branches, retries, failure states, or idempotency rules are missing.
  • Ask which package owns each DTO, port, repository, adapter, and runtime composition point.
  • Ask whether the proposed change violates AGENTS.md or existing architecture notes.
  • Ask what proof layer should cover the behavior before implementation starts.
