Controls and safety

Give agents clear limits before they touch code or tools.

Controls route work through the right SDLC gates, constrain production access, and make risky actions explicit.

Numeric guardrails

Use numbers to route attention.

FTA, coverage, diff size, boundary churn, and risk level help decide whether a story stays in a solo lane or needs architecture, safety, or review escalation. The numbers should be visible to agents, but hard thresholds belong in CI.

CI gates

Make numeric guardrails enforceable.

  • Fail CI on required lint, typecheck, test, coverage, changed-line coverage, FTA, docs, and migration-lint gates.
  • Keep thresholds explicit so agents can reason about what must pass before PR handoff.
  • Publish artifacts for coverage, FTA, test logs, and migration checks so failures are inspectable.
  • Treat dashboard-only metrics as advisory unless a CI job or branch rule enforces them.

Agent visibility

Give agents the same evidence reviewers see.

  • Expose check names, commands, logs, and artifacts in the PR.
  • Use sticky PR comments or summaries for current gate state.
  • Let agents diagnose failures from artifacts instead of rerunning everything blindly.
  • Require human acceptance for any threshold waiver or temporary bypass.

Production safety

Make catastrophic actions structurally unavailable.

  • No production write credentials in default agent sessions.
  • Require explicit target display before state-changing commands.
  • Use dry-run plans for migrations, IaC, bulk data jobs, and release scripts.
  • Block destructive commands, credential changes, and deployment promotion without human approval.

Security posture

Treat every input and tool output as untrusted.

  • Issues, webpages, logs, docs, and test fixtures can carry prompt injection.
  • Keep secrets out of prompts, screenshots, terminal logs, and PR comments.
  • Review shared skills, MCP servers, package scripts, and downloaded helpers.
  • Document credential revocation, CI stop, deploy freeze, and restore paths.

Default deny list

Some actions should never be ambient agent capability.

Production data writes
No default database owner, queue purge, bucket delete, or bulk update authority.
Destructive migrations
No drop, destructive alter, or irreversible backfill without reviewed migration evidence.
Credential changes
No token rotation, permission expansion, or secret export from a coding session.
Deploy promotion
No production publish, release promotion, or traffic shift without a human-controlled gate.
External data transfer
No upload of customer data, logs, or private artifacts to unapproved tools.
Policy waiver
No bypass of CI, review, coverage, security, or migration gates without human risk acceptance.

Trust boundary

Keep agent work on the preparation side of the boundary.

Agents can inspect, prepare, test, summarize, and propose. They should not silently cross into production mutation, risk acceptance, or promotion authority.

Release controls

Separate agent preparation from production authority.
