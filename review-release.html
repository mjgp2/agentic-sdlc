Review and release

Make the PR prove the story is ready for human judgment.

Model confidence is not a release gate. The handoff carries story context, changed files, test evidence, UAT status, risk notes, rollback path, and unresolved gaps.

PR evidence

Make the review package easy to audit.

Summary
What changed and which story outcome it supports.
Proof
Commands, test layers, manual checks, and UAT evidence.
Risk
Architecture, data, rollout, security, supply-chain, and performance notes.
Gaps
Anything not tested, deferred, or requiring human approval.

PR governance

Make metadata part of the gate.

  • Use Conventional Commit style PR titles: type(scope): summary.
  • Keep required body sections: summary, testing, release impact, and docs.
  • Let validation workflows check PR title, description, and release intent.
  • Keep “not tested” explicit instead of hiding verification gaps in prose.

CI artifacts

Use CI output as review evidence.

  • Quality logs and FTA reports explain maintainability gates.
  • Coverage HTML, summaries, and changed-line checks explain unit proof.
  • Integration and functional logs explain environment or runtime failures.
  • Sticky PR comments and dashboards show trend and gate state.

Required AI reviews

Make independent AI review a PR requirement.

A coding agent that produced the diff should not be the only model that inspects it. Require an independent AI review pass before human approval, and split the review into code quality and security concerns so both get explicit attention.

Code quality

Correctness and maintainability

Use Codex, Cursor, or a team review skill to check logic defects, missing tests, unclear names, architecture drift, excessive complexity, and inconsistent TypeScript patterns.

Required before human review
Security

Trust boundaries and abuse paths

Run a separate security review for auth, data access, injection risk, secrets, dependency changes, unsafe scripts, destructive operations, and production-impacting configuration.

Required for every material PR
DB migration

Schema and data safety

For migrations, require migration lint/static checks plus a specialist agent review for locking, reversibility, backfill safety, destructive changes, and rollout order.

Required for schema/data changes
Human gate

AI comments are evidence, not approval

Treat AI review output like CI: useful signal that can block or focus the review. Merge authority, risk acceptance, UAT signoff, and release timing remain human-owned.

No auto-merge on model confidence

Review loop

Run the AI quality loop before normal human review.

The post-PR agent loop is a hardening step: cleanup, independent code review, CI repair, PR body updates, and review-state checks. It should finish with no unresolved actionable AI comments. After that, the human reviewer uses GitHub normally, leaves comments, and asks the agent to fix and reply with evidence before re-review.

Handoff prompt

Ask the agent for evidence in the PR shape.

PR package

Prepare the PR handoff.
Include:
- Summary mapped to the story outcome.
- Testing with exact commands and CI artifact references.
- Independent AI code quality and security review status.
- DB migration lint and specialist migration review status when applicable.
- Release impact and docs status.
- Scenario ids covered and any coverage-matrix updates.
- Risks, supply-chain/provenance impact, rollback path, vulnerability response, and not-tested gaps.

Review loop

Address PR feedback in a loop.
Classify each comment as actionable, ambiguous, or external.
Patch actionable repo-local issues.
Rerun the narrowest relevant proof.
Reply only after the code and verification support the response.
Update the PR evidence before asking for re-review.
