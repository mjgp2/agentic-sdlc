Operating model

Make the agent's way of working explicit.

AI coding is more reliable when the repository contains the operating contract: environment setup, tool choices, skill usage, and expected evidence.

AGENTS.md

Repo-local guidance beats repeated prompting.

  • Document environment setup such as nvm use, pnpm commands, and local services.
  • Encode architecture rules, naming conventions, package boundaries, and SQL patterns.
  • Specify validation commands and what counts as done.
  • Keep always-loaded guidance short; move path-specific rules or workflow playbooks into scoped files or skills.
  • Keep guidance decision-oriented: rule, reason, proof.

Performance

Optimize the loops agents run repeatedly.

  • Use pnpm shared stores, reproducible installs, and documented worktree bootstrap.
  • Keep pnpm install fast enough that fresh worktrees are cheap to create.
  • Separate fast focused checks from full CI parity.
  • Design test commands so independent unit, integration, and functional lanes can run in parallel.
  • Keep typecheck, lint, and test commands documented and stable.
  • Watch warm-loop timings because agent workflows repeat checks frequently.

Context management

Give the agent the smallest useful context pack.

  • Include the ticket, relevant repo text, diagrams, failing logs, expected outputs, and commands.
  • Summarize long threads before handoff instead of pasting the whole conversation history.
  • Use checkpoints or clean commits before long-running agent work so recovery is cheap.
  • Use ignore files to keep secrets, generated noise, and irrelevant bulk out of model context.

Parallel agents

Parallelize investigation without creating edit races.

  • Use subagents for read-only investigation, verification, and focused review.
  • Use separate worktrees when multiple agents may edit code.
  • Assign file ownership or task slices before parallel implementation starts.
  • Merge findings through one owner who decides what reaches the PR.

Mode selection

Choose the smallest operating mode that fits the work.

The mode is part of the task design. It sets how much planning, specialization, parallelism, and review loop machinery the agent should use.

Direct

Solo execute

Use for scoped, reversible changes where one agent can inspect, edit, verify, and report.

Default lane
Skill

Named workflow

Use for recurring work: code review, security review, PR comment loops, CI repair, cleanup, and quality checks.

Reusable stop condition
Plan/team

Coordinated work

Use planning or team modes when requirements are unclear, risk is high, or independent lanes can run in parallel.

Higher coordination cost

Skills and loops

Turn recurring work into named workflows.

Skills and oh-my-codex workflows are useful when they encode repeatable team judgment: PR loops, CI repair, code review, cleanup, security review, and quality checks.

PR loop

Review feedback

Collect comments, fix actionable issues, push, re-check, and stop only when review state is clean.

Quality loop

Self-review

Run focused review for bugs, missing tests, architecture drift, and slop before human review.

CI loop

Repair checks

Inspect failing jobs, identify the command and failure mode, patch locally, and rerun the right check.

Architecture contract

Write rules that constrain actual edits.

  • Package ownership: which module owns DTOs, ports, repositories, stores, and runtime composition.
  • Naming: *Service, *Repository, *Store, controller/route suffixes.
  • SQL shape: static commands, bound values, narrow allowlists for dynamic identifiers.
  • Script posture: namespaced scripts under scripts/dev, scripts/test, scripts/quality, and scripts/release.

Commit knowledge

Use commits as decision records.

  • Write the first line as intent: why the change exists.
  • Use trailers such as Constraint, Rejected, Tested, and Not-tested.
  • Record rejected alternatives so future agents do not rediscover them.
  • Include forward-looking directives for fragile boundaries or operational constraints.

Operating prompt

Give the agent the operating lane.

Agent lane

Work from the ticket and repo guidance.
Use a fresh worktree.
Follow AGENTS.md for setup, architecture boundaries, and verification.
Use shared skills for PR review loops, CI repair, and quality checks when applicable.
Report changed files, checks run, risks, and not-tested gaps.

Skill request

Use the team skill for this workflow.
State the stopping condition before starting.
Separate repo-local actionable failures from external blockers.
After each fix, rerun the narrowest proof that could fail.
