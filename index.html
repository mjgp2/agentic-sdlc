The method

Agentic SDLC means the agent works inside delivery controls.

The core move is simple: turn each lifecycle step into repo text, give the agent an isolated lane to act in, enforce objective gates in CI, require independent review, and keep production authority human-owned.

A useful mental model is a team of very fast junior developers: capable of producing useful code, but needing clear scope, good examples, review, feedback, and limits before the work is trusted.

Repo text Worktree lane CI gates AI review Human release

Why it exists

Unmanaged AI coding does not fail politely.

The risk is not that the agent writes code. The risk is that it writes code outside the team’s normal contract: no clear scope, no durable design context, no reproducible proof, no independent review, and no controlled release path.

Scope expands silentlyThe agent fixes adjacent problems because the ticket did not name non-goals.
Architecture driftsPackage boundaries, data ownership, and migration posture live in someone’s head.
Proof is theatricalCoverage exists, but scenarios, negative paths, CI artifacts, and UAT evidence do not line up.
Release risk hidesCredentials, migrations, deploy promotion, and rollback are treated as implementation details.

Adoption path

You do not need the whole model on day one.

Start by making one user story legible to an agent and a reviewer. Add gates as risk, team size, and production exposure increase.

Post-PR hardening

The PR is not ready for human review just because it exists.

After opening the PR, run a quality loop first. In this guide that means: clean obvious slop, run an independent AI code review, fix actionable findings, update the PR evidence, inspect CI, and stop only when there are no AI findings that still need action. Then the human reviewer uses the normal PR review system, and the agent fixes and replies to those comments before re-review.

Text-first rule

Put the agent's operating context in the repo.

Use Markdown specs, Mermaid diagrams, scenarios, ADRs, AGENTS.md, runbooks, and prompt kits so the agent reads the same reviewable source material as the team.

Power-ups

Use tools to reinforce the flow.

Worktrees, skills, oh-my-codex loops, guardrails, hooks, CI, and safety controls are accelerators for this map, not a replacement for the map.
