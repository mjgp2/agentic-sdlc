Example skills

Create shared workflows for repeated PR work.

Skills are useful when they capture work the team runs again and again: PR cleanup, code review, security review, CI repair, release handoff, and documentation checks. Keep each skill narrow enough that it has a clear stopping condition.

PR quality loop

Harden after opening

After the PR exists, clean slop, run code review, fix actionable findings, update PR evidence, monitor CI, and stop only when no AI findings still need action.

Required before human review
Security review

Threat-model the change

Check auth, data access, injection, secrets, dependency changes, unsafe scripts, and production-impacting configuration.

Run as a separate pass
DB migration

Protect schema changes

Run migration lint and specialist review for locking, reversibility, backfills, destructive changes, and rollout order.

Required for migrations
CI repair

Follow the failing signal

Read failing jobs, reproduce locally when possible, patch the cause, and rerun the check that proved the failure.

Stop when checks are clean

Skill snippets

Seed a team skill library.

PR quality skill

name: pr-quality-loop
description: Harden a pull request before human review by cleaning slop, reviewing the diff, fixing actionable findings, updating PR evidence, and checking CI/review state.

Workflow:
1. Identify the PR scope, changed files, repo guidance, and relevant test tiers.
2. Clean obvious slop without broadening beyond the PR diff.
3. Run independent code review and fix actionable repo-local findings.
4. Update the PR body with cleanup, fixes, tests, risks, and not-tested gaps.
5. Inspect CI and review state; loop until checks pass and no actionable AI findings remain.
6. Stop before merge. Human review, risk acceptance, and release authority remain human-owned.

Security review skill

name: pr-security-review
description: Review a pull request for security, privacy, secrets, and production safety risks.

Workflow:
1. Identify trust boundaries, auth paths, data access, and external inputs.
2. Check for prompt injection, SQL/script injection, secret leakage, unsafe dependencies, and destructive operations.
3. Mark each finding as blocking, non-blocking, or requires human risk acceptance.
4. Do not approve release. Produce evidence for the human reviewer.

DB migration skill

name: db-migration-review
description: Review database migrations for safety, rollout, reversibility, and operational risk.

Workflow:
1. Read migration files, schema diagrams, affected queries, and rollback/forward-fix notes.
2. Run or verify migration lint/static checks.
3. Check locking, long-running operations, backfills, destructive changes, defaults, indexes, and rollout order.
4. Mark findings as blocking, requires human risk acceptance, or non-blocking.
5. Produce PR evidence; do not approve production promotion.

Diagram examples

Keep complex behavior visible as text.

Sequence diagram

```mermaid
sequenceDiagram
  participant User
  participant API
  participant Service
  participant Database
  User->>API: Submit request
  API->>Service: Validate command
  Service->>Database: Persist state change
  Database-->>Service: Commit result
  Service-->>API: Domain outcome
  API-->>User: Response plus trace id
```

Review with AI:
- What retries, idempotency checks, or failure branches are missing?
- Which participant owns validation, persistence, and audit logging?

erDiagram

CI examples

Make gates enforceable, not advisory.

Gate matrix

| Gate | Enforced where | Artifact |
| --- | --- | --- |
| Format/lint/typecheck | pre-push and CI | job log |
| Unit coverage | CI branch rule | coverage summary |
| Changed-line coverage | CI branch rule | changed-lines report |
| FTA/complexity | CI branch rule | FTA report |
| Migration lint | CI for schema changes | migration output |
| AI quality review | PR required check/comment | review findings |
| AI security review | PR required check/comment | risk findings |

Resource rules

Keep examples close to real team practice.

  • Prefer repo-local Markdown and Mermaid over transient chat instructions.
  • Version skills and templates like code, because they shape code.
  • Document the stop condition for each repeated workflow.
  • Retire examples that no longer match CI, hooks, or architecture guidance.

Useful examples

Point resources at the workflows people actually run.

  • AGENTS.md for repo-wide operating rules.
